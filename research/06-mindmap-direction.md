# 06. 마인드맵 방향 조사 (2026-10-09)

대상: 사용자 평가 "마인드맵이 완전 구려, 너무 요약되어 있고 보고 나서 뭐가 뭔지 모르겠어."
읽은 것: `backend/app/mindmap.py`, `web/src/components/Mindmap.tsx`, `web/node_modules/markmap-view/dist/index.js`, 예시 `data/media/78f1gpZXz4k-1791302454/mindmap.md`, 같은 노트의 report·transcript(`data/notes.db`), `design-ref/app-result-mindmap_PC_light.jpg`.
코드는 고치지 않았다. 웹 조사는 WebSearch/WebFetch 요약과 `gh api`(라이선스 원문)로만 했다. 화면·원문 확인이 필요한 것은 맨 끝 `chrome_worklist`에 있다.

## 1. 진단: 무엇이 문제인가

| # | 문제 | 근거(코드·데이터) | 결과로 생기는 일 |
|---|---|---|---|
| 1 | **처음 화면에 요점이 아예 안 보인다** | `initialExpandLevel: 3`. markmap은 루트를 depth 1로 세고 `depth >= 3`이면 접는다(`_initializeData`: `s >= 0 && a.state.depth >= s → fold`). 그래서 `###` 노드가 접힌 채로 시작하고 그 아래 `-` 요점은 숨는다 | 열자마자 보이는 건 "게리 탄과 G스택", "부탁과 강제의 차이" 같은 **제목 17개뿐**(요점 32개는 숨김). 내용을 보려면 동그라미를 11번 눌러야 한다 |
| 2 | **요점이 몇 단어짜리 조각이라 맥락·인과가 없다** | 프롬프트가 "각 줄 20자 안팎 명사구(문장 금지)"를 강제 | "전부 기계화하면 성능 낭비", "좀비 규칙 정리", "턴 종료 전 검사"처럼 **누가·왜·그래서**가 빠진다. 영상을 안 본 사람은 해독할 수 없다 |
| 3 | **입력부터 이미 잘려 있다** | `_text()`가 하위 주제마다 bullet을 **3개까지만**, 그것도 `" / "`로 이어 붙여 넘긴다. 1.2(5개)·3.2(5개)는 뒤 2개가 버려진다. `key_points`도 안 넘긴다 | 리포트에 있던 사실이 마인드맵에 오기 전에 사라진다 |
| 4 | **숫자·사례·고유명사가 빠진다** | 리포트엔 "23개 역할", "10분에 쓴 코드를 3시간 검수", "규칙 20개 넘게", "DB 구조 변경 100번 넘게 무사고", "미첼 하시모토", "에디 오스만"이 있는데, 마인드맵엔 23개·22시간·10만 정도만 남는다 | "검증 계층이 중요하다"는 말만 있고 **왜 믿어야 하는지(사례)**가 없다 |
| 5 | **시간 출처가 없다** | 리포트 bullet마다 `refs`(대본 문단 번호 → 시각)가 있는데 프롬프트로 안 넘기고, 출력 형식에도 없다 | 궁금한 요점을 영상에서 확인할 길이 없다(릴리스 요약·Mapify는 시각 이동이 핵심 기능) |
| 6 | **섹션이 합쳐지고 끝부분이 뭉개진다** | 리포트 6개 섹션 → 프롬프트 "3~5개" 제한 때문에 5·6이 "실전 적용과 강의 안내"로 합쳐짐. "화자의 장치와 강의" 아래에 '턴 종료 전 검사'와 '22시간 강의'가 같은 급으로 섞임 | 핵심(검증 세 지점)과 광고(강의)가 같은 무게로 보인다 |
| 7 | **노드를 눌러도 아무 일이 없다** | `Mindmap.tsx`에 클릭 처리 없음. markmap 기본 `handleClick`은 동그라미 접기/펴기뿐 | 더 알고 싶어도 갈 곳이 없다(NotebookLM은 노드 클릭 → 채팅 질문) |
| 8 | **색이 가지를 구분해 주지 않는다** | `color`가 깊이(depth)별 보라 5단계. 같은 깊이는 모든 가지가 같은 색 | 화면에서 "이 요점이 어느 큰 주제 소속인지" 눈으로 못 따라간다. (릴리스도 보라 단색 계열이라 모방 면에서는 일치) |
| 9 | 글자가 작다 | 릴리스 캡처는 약 10px. 우리도 markmap 기본 글꼴, `maxWidth 200` | 긴 문장으로 바꾸면 더 빽빽해지므로 글자 13px·폭 280 정도가 필요 |

한 줄 요약: **"제목만 보이는 목차"를 마인드맵이라고 부르고 있다.** 내용(요점)은 접혀 있고, 펼쳐도 맥락 없는 단어 조각이며, 원문(리포트)에 있던 사례·숫자·시각은 입력 단계에서 이미 버려진다.

릴리스 캡처(`app-result-mindmap_PC_light.jpg`)도 노드 글이 "AI 역할과 순서 설계", "반복 개선"처럼 짧다. 즉 **릴리스를 그대로 따라 한 결과가 사용자에게 "구리다"는 평가를 받은 것**이다. 모양(markmap, 왼→오, 보라)은 유지하되 내용은 릴리스보다 자세하게 가는 것이 맞다고 본다(차이는 LILYS_CHANGES에 기록 필요).

## 3. 좋은 마인드맵 원칙과 근거

| 원칙 | 출처 | 우리에게 주는 뜻 |
|---|---|---|
| Buzan: 가지마다 **한 단어**, 중심 주제 + 주요 가지 5~10개, 가지별 색·이미지 | Buzan 방법 요약(muni.cz 등 ◐) | **스스로 만드는 지도**용 규칙. 한 단어는 만든 사람 머릿속 기억을 불러내는 "단서"라서 통한다. 남이 만든 지도를 받아 읽는 사람에겐 단서가 아니라 수수께끼가 된다 → 지금 사용자가 겪는 문제 그대로 |
| Novak 개념도: 두 개념을 **연결어(동사)**로 이어 "개념-관계-개념"이 **한 문장(명제)**이 되게 | 개념도 문헌(EPFL 백과 항목 등 ◐) | 노드 글에 "→ 그래서", "때문에", "예)" 같은 관계가 들어가야 읽는 사람이 이해한다. 단어만 있는 노드는 "관계가 비어 있는 명제"와 같다 |
| 개념도를 **공부(읽기)만 해도** 효과 있음: 남이 만든 지도를 공부한 경우 g≈0.37~0.43, 직접 만든 경우 g≈0.72~0.82. 지도 vs 개요·목록 비교는 g≈0.28(k=10)로 작음 | Nesbit & Adesope 2006 (Review of Educational Research 76:413), Schroeder 외 2017 (◐ 요약으로 확인, 원문 수치는 chrome_worklist) | ① 읽기용 지도도 도움이 되지만 **목록보다 크게 낫지는 않다** → 그림이 예쁜 것보다 **내용이 충실한 게 먼저**. ② "지도만 보고 이해"가 목표라면 노드마다 명제(문장) 수준 정보가 필요 |
| 효과는 맥락·설계에 따라 다름 | 2025 체계적 고찰(◐) | 일반론보다 우리 사용자 반응(“뭐가 뭔지 모르겠다”)이 더 강한 근거 |

정리하면, **"읽는 사람용 요약 지도"는 Buzan식 한 단어가 아니라 개념도식 짧은 문장(명제)**이어야 하고, 노드마다 **근거(숫자·사례)**와 **원문 위치(시각)**가 붙어야 이해·검증이 된다.

## 5. 추천 방향 (1개): "설명형 마인드맵" — markmap 유지, 내용·펼침·클릭을 바꾼다

| 항목 | 지금 | 바꿀 것 |
|---|---|---|
| 노드 글 형식 | 전부 20자 명사구 | `#` 루트 = **영상 한 줄 결론(문장)** / `##` = 리포트 섹션 제목(주장형, ≤20자) / `###` = **"소주제 — 한 줄 결론"**(≤45자, 왜·그래서 포함) / `-` = **사실 한 개를 담은 짧은 문장**(≤55자) + 숫자·고유명사·사례 중 하나 이상(숫자는 `**굵게**`, 사례는 `예)`) + 끝에 `[m:ss]` |
| 깊이·개수 | 4단계, 섹션 3~5 | 4단계 유지. **리포트 섹션 수 그대로(1:1, 합치지 않음)**, 하위 2~3, 잎 2~4. 총 40~60노드 |
| 처음 펼침 | `initialExpandLevel: 3` → 잎 숨김 | **전부 펼침**(`-1`) + 화면 맞춤. 광고·채널 소개 같은 부록 가지만 `<!-- markmap: fold -->`로 접어 둠 |
| 노드 클릭 | 없음(동그라미 = 접기) | ① `[m:ss]` 클릭 → 왼쪽 영상·스크립트를 그 시각으로 이동(이미 있는 타임스탬프 이동 재사용). ② 노드 글 클릭 → 오른쪽 채팅 입력창에 "「노드 글」 부분을 자세히 설명해줘" 채우기(NotebookLM 방식). ③ 동그라미 = 접기(그대로) |
| 색 | 깊이별 보라 5단계 | **가지(`##`)별 색**(`colorFreezeLevel: 2`), 첫 색은 릴리스 보라 `#6663fd`, 나머지 차분한 4~5색. ※ 릴리스(깊이별 보라)와 다름 → LILYS_CHANGES 기록 |
| 글자·폭 | 기본 크기, `maxWidth 200` | 글자 13px, `maxWidth 280`, `spacingVertical 10` |
| 레이아웃 | 왼→오 트리 | 그대로(릴리스·NotebookLM과 같음) |
| 생성 입력 | 리포트 제목·개요 + bullet 3개씩 이어 붙임 | **리포트 전체**(key_points + 모든 bullet 원문, 잘림 없이) + bullet마다 `refs[0]`의 대본 시각(`m:ss`). **대본 전체는 넣지 않는다**: 리포트가 이미 대본에서 뽑은 사실·숫자·refs를 다 갖고 있어 정보는 충분하고, 대본(이 노트 978초, 63문단)을 넣으면 입력이 몇 배로 늘어 시간만 길어진다. 시각은 코드가 계산해 넘기므로 AI가 지어낼 일도 없다 |
| 프롬프트 핵심 문장 | "20자 명사구, 문장 금지" | "영상을 안 본 사람이 이 지도만 보고 내용을 설명할 수 있게. 잎은 사실 하나를 담은 짧은 문장, 숫자·이름·사례를 지우지 말 것, 리포트에 없는 내용 금지, 각 잎 끝에 주어진 [m:ss]를 그대로 붙일 것" |
| 예상 생성 시간 | `claude -p` 120초 제한 안 | 입력 약 2.5천 자 → 약 7천 자, 출력 약 1천 자 → 약 3천 자. **추정 40~90초**(미측정). 시간 제한은 180초로 여유 있게. 릴리스도 1분 넘게 걸림(캡처 메모) |

차이(릴리스 대비): 노드 글이 더 길다, 가지별 색, 처음부터 전부 펼침, 시각·채팅 클릭. 모양(markmap 왼→오, 회색 박스, 하단 바)은 같다.

## 6. 차선 (1개): "뼈대 지도 + 클릭 시 상세 카드" — AI 재생성 없이 리포트를 코드로 변환

- 노드 글: 리포트의 섹션 제목 → `##`, 하위 제목 → `###`. 잎은 만들지 않거나 bullet 앞부분만.
- 클릭: `###` 노드를 누르면 지도 오른쪽/아래에 **상세 카드**가 열려 그 하위 주제의 bullet 원문 전체 + 각 `[m:ss]` 버튼을 보여 준다(데이터는 report의 `sections[].children[].bullets/refs`에 이미 있음).
- 장점: **생성 시간 0초**, AI 비용·환각 0, 리포트와 100% 일치. 단점: 지도 자체는 여전히 목차처럼 보여서 "지도만 보고 이해"는 안 된다(카드를 눌러야 함). 지도와 요약 리포트가 사실상 같은 내용의 다른 보기라 확장 템플릿으로서 새로움이 적다.
- 렌더러: markmap 그대로(노드 DOM에 클릭 리스너) 또는 Mind Elixir(`selectNodes` 이벤트).

추천을 1순위로 둔 이유: 사용자 불만이 "지도를 보고 나서 뭐가 뭔지 모르겠다"이므로, **지도 그 자체가 읽혀야** 한다. 차선은 클릭을 해야만 읽힌다.
